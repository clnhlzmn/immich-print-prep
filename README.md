A small web UI that sits next to your [Immich](https://immich.app) instance:
pick photos, adjust them for print, and download a zip of print-ready files.

It replaces doing this by hand in a desktop image editor. The default
conversion rotates landscape photos 90° counter-clockwise, pads to the 8×10
aspect ratio with white, sets 300 DPI, and resizes to 8×10 inches as JPEG.

A multi-arch Docker image is published to the GitHub Container Registry (GHCR).

## What it does

- **Sign in** with a username from the server config file and a password you
  choose on first sign-in. There is no sign-up flow.
- **Bring your own Immich API key.** Each user pastes their own key, so everyone
  sees exactly the photos Immich lets them see. The key is encrypted at rest and
  never reaches the browser — thumbnails are proxied through the server.
- **Choose photos** by album, by tag, from the whole timeline, by file name, or
  with Immich's contextual (smart) search. Select individually, shift-click a
  range, or add everything in an album/tag/search at once.
- **Adjust the print set** in bulk or photo by photo: print size, orientation,
  pad or crop-to-fill, pad colour, DPI, JPEG quality, output format, and a
  draggable crop box locked to the print ratio. Every card shows a proof of the
  finished file, rendered by the same code that writes the zip.
- **Download** a zip. The server pulls the originals from Immich, converts them,
  and streams the result, with a progress bar and a per-photo manifest.
- **Keep a record.** Optionally create an Immich album and/or tag named
  `<datetime>-print-set` holding everything you just downloaded. The choice and
  the names are set per print set, right beside the Prepare button, pre-filled
  from your saved defaults. Names are stamped with your browser's local time,
  not the server's.

```yaml

services:
  immich-print-prep:
    image: ghcr.io/clnhlzmn/immich-print-prep:latest
    restart: unless-stopped
    ports:
      - "8000:8000"
    volumes:
      - ./config.yaml:/config/config.yaml:ro
      - ./data:/data
```

```yaml
# config.yaml
immich_url: "http://immich-server:2283"
users:
  - colin
```

```
docker compose up -d
```

Then open <http://localhost:8000>, sign in as `colin` (any password — the first
sign-in claims the account), choose a password, and paste an Immich API key when
the settings panel opens.

### API key permissions

Immich creates keys under **Account Settings → API Keys**, with per-key
permissions. This app needs:

| Permission | Why |
| --- | --- |
| `album.read` | List albums and their contents |
| `asset.read` | Search, and browse the timeline |
| `asset.view` | Thumbnails and the preview each proof is rendered from |
| `asset.download` | Fetch the originals that go into the zip |
| `tag.read` | *(optional)* browse by tag |
| `album.create`, `albumAsset.create` | *(optional)* record a download as a new album |
| `tag.create`, `tag.asset` | *(optional)* tag what you downloaded |

Note that `user.read` is **not** required — the app never needs to read your
Immich profile, and a key saves fine without it (the settings panel just cannot
show which account it belongs to).

## Configuration

The config file is the only place accounts are defined. See
[`config.example.yaml`](config.example.yaml) for the annotated version.

| Key | Default | Meaning |
| --- | --- | --- |
| `immich_url` | *(required)* | Immich site root, reachable from the container. A trailing `/api` is trimmed. |
| `users` | *(required)* | List of usernames, or mappings with `username` and optional `initial_password`. |
| `allow_blank_first_login` | `true` | Whether an account with no `initial_password` can be claimed with any password. |
| `secret_key` | generated | Signs sessions and encrypts stored API keys. Generated into `<data_dir>/secret.key` if unset. |
| `data_dir` | `/data` | Database, thumbnail cache, prepared zips. |
| `session_days` | `30` | How long a sign-in lasts. |
| `verify_tls` | `true` | Set `false` for an Immich instance with a self-signed certificate. |
| `site_title` | `Immich Print Prep` | Shown in the header and tab. |
| `defaults` | 8×10 at 300 DPI | Server-wide default print settings; each user can override them in the UI. |

`IPP_CONFIG`, `IPP_DATA_DIR`, `IPP_IMMICH_URL`, `IPP_SECRET_KEY`, `IPP_HOST`,
`IPP_PORT` and `IPP_LOG_LEVEL` override the file. `python -m immich_print_prep
--check-config` validates a config and exits.

### Accounts and first sign-in

An account listed as a bare name has no password until someone claims it, and
the first sign-in is what claims it — so claim yours as soon as the server is
up. To close that window, give the user an `initial_password`; it is then
required to claim the account and must be replaced immediately:

```yaml
users:
  - username: alice
    initial_password: "change-me-on-first-login"
```

Passwords are stored as scrypt hashes. Changing a password signs out every other
device. There is no password reset: to reset one, stop the container and delete
that user's row from `users` in `<data_dir>/print-prep.db`, or give them an
`initial_password` and delete the row.

## The print pipeline

Each photo is processed in this order:

1. Apply the EXIF orientation, convert to sRGB, and drop the source profile and
   metadata.
2. **Rotate.** `auto` (the default) turns landscape photos 90° counter-clockwise
   and leaves portrait ones alone; `none`, `cw`, `ccw` and `180` are explicit.
3. **Crop**, if you dragged a crop box for that photo.
4. **Fit** to the print size: `pad` scales the whole photo to fit and fills the
   remainder with the pad colour (white by default); `crop` scales to fill and
   trims the overflow.
5. **Resize** to `width_in × height_in` at `dpi` — 8×10 at 300 DPI is 2400×3000
   pixels — and write the DPI into the file so print shops honour it.
6. **Encode** as JPEG (quality 95, 4:4:4 chroma), PNG or TIFF.

`allow_enlarge` decides what happens to a photo smaller than the print: on by
default it is scaled up, off it is centred on a full-size canvas instead.

### Source formats

JPEG, PNG, HEIC/HEIF (what phones shoot), WebP, AVIF and TIFF are decoded from
the original file. For anything else Immich can display but this server cannot
read — camera raw, mainly — the print is made from Immich's own full-size JPEG
rendition rather than dropping the photo, and the manifest names the files that
took that route.

The zip also contains `print-set-manifest.txt`, listing each output file, its
source, and the settings used.

## Development

```
python -m venv .venv && ./.venv/bin/pip install -e ".[dev]"
./.venv/bin/pytest -q          # unit, end-to-end and (optionally) browser tests
./.venv/bin/ruff check .
./.venv/bin/python -m immich_print_prep --config ./config.yaml --port 8000
```

The test suite starts a stand-in Immich server (`tests/fake_immich.py`), so no
real instance is needed. `tests/test_browser.py` drives the whole UI in Chromium
— from first sign-in to the finished zip — and is skipped unless Playwright is
installed:

```
./.venv/bin/pip install playwright && ./.venv/bin/playwright install chromium
```

The front end is plain ES modules in `immich_print_prep/static/` — no build
step, no bundler.

## Notes and limits

- Only image assets are offered; videos are filtered out.
- A print set holds up to 2000 photos.
- Prepared zips are kept for 12 hours, then deleted. The thumbnail cache is
  capped at 512 MB and trimmed least-recently-used first.
- Nothing is ever written to Immich except the optional album and tag.
- Immich lets you add a partner's photos to **your album**, but not tag them:
  tagging is owner-only on their side. A print set mixing your photos with a
  partner's will file completely into an album, while the tag covers only your
  own — the download dialog says so when it happens.
- Put it behind your usual reverse proxy for TLS; the app trusts
  `X-Forwarded-Proto` when deciding whether to mark cookies `Secure`.
